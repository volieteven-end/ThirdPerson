## 1. 结论与设计定位

这批资源足以组成一套完整的**第三人称单剑动作系统**，不只是四段普通攻击。建议主循环为：

```text
移动接近 → 四段普攻 / 冲刺斩
                ├→ 闪避取消 → 重新找位置
                ├→ 蹲姿升龙 → 空中连击 → 下砸落地
                └→ 弹反成功 → 反击

敌人受击 → 普通硬直 / 击退 / 击飞 → 落地 → 倒地 → 起身 → 恢复 AI
任何阶段死亡 → 终止战斗逻辑 → 播死亡动画 → 尸体清理
```

先把**一套四段连击 + 防御 + 四向闪避 + 受击闭环**做好，再加入空战与特殊招式。第二、三套连击作为招式变体、精英敌人招式或升级解锁，不直接把十二个片段顺序塞进一个普攻数组。若以后继续向幸存者玩法发展，升级可以替换终结技、增大攻击范围或增加效果，不必再增加很多按键。

## 4. 动作状态与职责分开

不要用一排互相独立的 `bAttacking / bDodging / bBlocking / bHit` 决定一切。建议使用两个维度：

```text
MovementContext = Ground / Air
ActionState = Free / Attack / Dodge / Guard / HitReact / Knockdown / GetUp / Turn / Skill / Dead
```

`Air + Guard` 合法，`Air + Attack` 合法；`Attack + Dodge` 不同时占用同一个全身动作通道。

| 层 | 职责 | 现有内容如何复用 |
|---|---|---|
| Enhanced Input / Character | 把输入变成意图，提供相机方向、地空状态和锁定目标 | 复用现有 IA / IMC；按键继续在 UE 映射 |
| 建议新增 `ActionComponent` | 检查入口条件、动作状态、输入缓存、取消窗口、动作实例 ID、移动 / 转向权限、结束清理 | 逐步收拢 Character 和 Combat 中重复的状态分支 |
| `CombatComponent` | 刀刃扫掠、目标去重、伤害 / 耐力结算、格挡与弹反判定、命中效果 | 保留现有武器和 Health/Stamina 组件关系；不要第二套重复扣血 |
| `ActionDefinition` / 武器数据 | 指定 Montage、允许的后续招式、命中类型、消耗、移动与转向策略 | 在现有 `WeaponDefinition` 上增加动作集引用，保留旧数组迁移期兼容 |
| AnimInstance / AnimGraph | 读取游戏状态输出姿态，负责移动混合和视觉过渡 | 不独立决定“敌人已经复活 / 起身完 / 还能打下一刀” |

### 每招建议包含的数据

```cpp
// 结构草案；本次未加入工程，不是已编译接口。
struct FActionDefinition
{
    FName ActionId;                    // Sword.Light.1 / Sword.Air.Dive
    TSoftObjectPtr<UAnimMontage> Montage;
    FName EntrySection;
    float PlayRate = 1.f;
    float StaminaCost = 0.f;
    float DamageMultiplier = 1.f;
    FName MovementPolicy;              // Input / RootMotionXY / Ballistic
    FName RotationPolicy;              // Movement / CameraAnticipation / Root / Frozen
    TArray<FName> AllowedNextActions;
    FName HitReactionProfile;          // Light / Launch / Knockback / Knockdown
};
```

运行时另外存 `ActionInstanceId`、当前 Montage 实例、缓存输入及命中集合。不要把本次攻击的受击对象存在 NotifyState 资产自身：同一资产可能同时服务多个角色。

## 5. 输入、预输入与取消

### 输入分配

| 操作 | 行为 |
|---|---|
| WASD | 相机相对移动；锁定后侧移 / 后退 |
| Shift + 移动 | 疾跑；默认建议锁定状态下前向才启用 Sprint，资源没有八方向 Sprint |
| 左键 Started | 地面普攻；疾跑时冲刺斩；空中时空中普攻；C 按住且在地面时升龙 |
| C 按住 / 松开 | 蹲下 / 站起；与左键组合不再新增物理按键绑定 |
| 右键按下 | 开始短弹反窗口；长按自然转持续防御 |
| 右键松开 | 若仍在短弹反窗口则保留到窗口结束；否则退出防御 |
| Alt + WASD | 四向根运动闪避；没有方向输入时使用角色前方 |
| Space | 跳跃，是否二段跳由能力决定 |
| 锁定键 | 复用现有 IA_LockOn，不改变已有映射 |
| 后续重击 / 下砸 | 新建 IA_HeavyAttack，可在 IMC 选择 Q 等未占用键；空中该输入触发下砸 |

同帧判定顺序：先检查 Dead / 操作禁用 → 当前动作是否允许切换 → 地空上下文 → C 升龙 / Sprint 起手 / 普攻。优先使用真实 IsFalling，避免下落时 C 还保留导致地面升龙。

### 两种缓存，不混成一个无限队列

1. **连击预输入**：当前普攻开始后允许提前记住“一次下一刀意图”；绑定当前 ActionInstanceId，保留到本段 ChainPoint。一次点击只消费一次，不会连点五次后自动打完五刀。
2. **通用短缓存**：跳跃、闪避、落地攻击使用约 0.15～0.25 s 的有效期。受击、死亡、打开菜单和重新开始时清空。
3. 当前动作被打断时作废其连击意图；上一段 Notify / MontageEnded 回调必须核对动作实例，防止清掉刚开始的新动作。
4. 普攻第一版推荐 `Started` 入队，持续按住左键不自动累计输入；以后增加连按辅助选项再单独配置。

### 现在的连段为什么仍可能慢

| Montage | 总长 | Damage 窗口 | ComboInput 窗口 | 现有代码真正接段时刻 |
|---|---:|---|---|---:|
| AM_Sword_Attack_01 | 1.633 | 0.214～0.356 | 0.426～1.247 | 1.247 |
| AM_Sword_Attack_02 | 1.883 | 0.223～0.408 | 0.535～0.991 | 0.991 |

建议把“记录输入”和“接段时刻”分开：保留提前记录，另加单点 **ChainPoint Notify**。第一轮可试 1→2 在 0.50～0.65 s、2→3 在 0.50～0.65 s、3→4 在 0.60～0.75 s；这些是调试起点，需按下一段起始姿态和刀轨调整，不是已验证的命中帧。

源整套 `Attack_Combo_01_Anim` 仅 3.033 s，四个拆分片段总长约 7.283 s：拆分片段包含回收尾段，连击不应每刀都等完整归位。把整套动画当作节奏参考，而不是直接提高所有动画倍速。

### 取消规则

- Dead 最高优先级，从任何动作进入并阻止后续恢复逻辑重开战斗。
- 普通攻击 Active 伤害段不允许普通输入随便取消；Recovery 开放 Dodge / Guard，特殊招式可不同。
- 受击是否打断先经过无敌 / 霸体 / 格挡结算，再决定，不单靠优先级数字。
- 闪避只在配置的无敌窗口内免伤；动作有位移不等于整段无敌。
- 第四刀作为终结段，建议有短承诺后摇；完成后再消费新起手，不自动无限环回。
- 所有结束路径共用清理：结束扫掠、停刀光、清 Warping Target/Modifier、清缓存、恢复移动与旋转策略。正常结束、受击中断、死亡、资源播放失败都覆盖。

## 6. 位移与转向：一个阶段只交给一个控制者

### 位移策略

| 动作 | WASD | 位移来源 |
|---|---|---|
| 自由移动 / 蹲走 | 允许 | CharacterMovement |
| 地面攻击 | 禁止移动输入 | Montage 根运动 XY；需要时在短窗口做 Warping |
| 闪避 | 启动时读取方向，过程中不重新选方向 | 四个 Montage 的根运动；不同时 LaunchCharacter |
| 地面格挡 | 禁止移动输入 | 第一版不移动；进入防御时消除地面残余滑动 |
| 空中格挡 | 禁止新增移动输入，保留当前速度 | 重力和原有惯性；不要 StopMovementImmediately |
| 升龙 / 下砸 / 被击飞 | 依据动作限制输入 | 垂直运动归 CharacterMovement；Launch 只在动作提交点执行一次 |
| 普通受击 / 倒地 / 起身 | 禁止移动输入 | 每个反应选根运动或代码击退一种，不叠加 |
| Dead | 禁止 | 由死亡方案决定根运动或原地；攻击逻辑先结束 |

普通跳跃和受击空中的高度以物理为准，动画根高度需提取 / 锁定或制作 in-place 派生资源，避免角色胶囊跳一次、骨骼又跳一次。UE 的 Walking / Falling 通常仍由重力控制 Z，不能假设勾选根运动就完全复现动画里的飞行轨迹。[Epic 根运动文档](https://dev.epicgames.com/documentation/unreal-engine/root-motion-in-unreal-engine)

实测四个闪避片段都已开启根运动，时长均 1 s，净水平位移约 **478 / 485 / 501 / 483 cm（前 / 后 / 左 / 右）**。原始根轨迹路程略大于净位移，CSV 分别记录。若想缩到约 3 m，应调整根运动位移缩放或有界目标修正；提高 PlayRate 主要缩短时间，不会等比例缩短整段距离。

资产原始根轨迹中 +Y 是前向；当前角色 Mesh 的相对 Yaw=-90°，把它转成角色局部 +X。不要看到资产 Y 位移就把输入 X/Y 对调。

### 转向策略

| 阶段 | Yaw 控制者 |
|---|---|
| 未锁定移动 | OrientRotationToMovement |
| 锁定移动 | 正常锁定朝向逻辑，限制转速 |
| 攻击前摇 | 对准本次相机 / 锁定目标方向，短窗口修正 |
| 攻击出刀至主要回收 | 冻结目标方向或只允许很小修正，避免攻击中追着目标转圈 |
| 闪避 | 固定启动朝向；按输入选前后左右动作 |
| TurnAction | 根旋转 Montage 独占；结束不再加 90° / 180° |

四个 Turn 原始累计根旋转实测约 -90 / +90 / -180 / +180°，其中 180° 用逐采样角差累计，避免只看首尾角度把左右混淆。建议初版用 55° / 135° 两档触发阈值，动作开始时锁定选中的枚举，不每帧重选；结束后余角小于阈值就停，不瞬间硬对齐相机。

UE 落地步骤：复制四个 Turn Sequence 作为动作系统派生资源，开启 Enable Root Motion（当前四个都是关闭），从它们创建四个 Montage。现有序列都带有 `CommitTurn` 通知：派生版本去掉该通知，或让其只报告动作阶段而不再调用 `CommitTurnInPlace()` 叠加角度。旧转身状态路径与新 TurnAction 不同时启用。

Motion Warping 只是**在指定窗口修正根运动**，不是相机系统。目标名统一 `AttackTarget`。建议冻结目标到每次起手，或只在前摇更新；补上最大修正距离、碰撞约束和目标丢失处理。目标点在敌人胶囊外，而不是敌人中心。[Epic Motion Warping 文档](https://dev.epicgames.com/documentation/unreal-engine/motion-warping-in-unreal-engine?lang=en-US)

目前角色代码生成的攻击目标 Z 是角色中心高度，而几个 Montage 勾选了 Warp to Feet Location。后续必须统一为“胶囊中心”或“脚底”一种约定；当前 Ignore Z Axis=true 不能替代整体约定。基础前摇之外不再同时让锁定 ControllerYaw、代码 RInterp 和根运动都写角色旋转。

## 7. 防御、受击与空战闭环

### 格挡和弹反

```text
按下右键 → Parry 短窗口（沿用现有 0.22 s 起测）
  ├ 命中 → 0 伤害 + 敌人 AM_EnemyParryStagger + 一次反击机会
  └ 到期 → 仍按住：Guard Hold / 已松开：Block Out → Free

Guard Hold 被击中 → 扣耐力 + 减伤 + Block Hit
  ├ 仍按住且耐力足够 → 回 Guard Hold
  └ 耐力耗尽 → Block Breach → 恢复结束 → Free
```

沿用当前测试基准：格挡后伤害 25%、每击消耗 15 耐力、前方 120° 防御角。它们是游戏平衡起点，不是资源约束。普通长按格挡不把敌人打硬直；只在有效弹反窗口触发反制。空中挡住不清零横向和竖向速度，不让角色悬停。

### 升龙与敌人击飞

```text
升龙真实命中 → 结算 LaunchHit
              → 终止敌人攻击窗口、移动请求和当前攻击
              → AirHitStart → AirHitLoop
              → 确认 Landed / 有效地面接触
              → LandImpact → DownIdle → GetUp
              → 起身完成且存活 → 恢复 AI
```

不要把“硬直计时结束”直接当作“可以站起来”。空中超时可作为异常保护，但必须转继续下落的姿态，不在空中启用地面 AI。

姿态配对：两套 `Down_01` 与 `Down_02` 的起始倒姿不同。通过本次骨骼图检查，`Hit_Drop_01_End` 与 `Hit_Drop_03_End` 都有明显躺倒终态；实际选择哪套 Down/Getup 要在 UE 用同一个网格检查朝向及第一帧对齐，不随机混用。倒地后被补刀播放对应 Down_Hit，再回同一 Down_Idle。

### 空中连击和下砸分开

- 空中左键：01→02，最多两段起步；只有限度调整空中速度，不每刀把 Z 重设为相同向上速度。空中段数 / 敌人浮空次数受限，落地重置，防止无限浮空。
- 下砸输入：05_In→05_Loop；接触地面后进入着地段。**05_Out 起始还有从倒置姿态落地的动画**，不能落地才从远高于地面的整段首帧机械播放。需在 UE 划定 Out 中的实际着地点：提前用离地距离进入 Out，或截取接触后的恢复段，在物理落地时播放后半段。
- 06_In/Loop/Out 暂作第二种技能储备，同样先找接触帧再设计退出条件。
- 多段循环伤害每个 HitGroup 只命中一次或有显式冷却，不能每帧或每个极短 Loop 都重复扣血。

### 死亡

死亡发生时先标记 Dead，取消命中窗口、动作缓存、计时器、AI 攻击与移动，再播死亡动画。死亡 Montage 结束只允许尸体处理，不允许正常 Combo / GetUp 回调恢复战斗。

本文件夹 `AM_Dead` 长 4.633 s；当前主角 Death Montage 默认值实际指向其他文件夹的 `AM_EnemyDeath`。若选择改用 AM_Dead，尸体不能仍固定 2 秒硬消失而截断演出：建议动画完成后再延迟清理，或明确选择短死亡演出并裁定可见结束点。玩家死亡后进入死亡界面，Restart 统一复位动作 / 输入模式、速度、计时器、相机与鼠标状态。

## 8. AnimGraph 与 UE 中的搭建方式

### 推荐初版图结构

```text
Locomotion 状态机
  ├ Ground：BS_SwordLocomotion
  ├ CrouchEnter → CrouchLoop（BS_Crouch_Locomotion）→ CrouchExit
  ├ JumpStart → JumpLoop → JumpEnd
  └ GuardEnter → GuardHold ↔ GuardHit → GuardExit

Locomotion 输出
  → Slot（DefaultSlot）
  → Inertialization
  → 足部 IK / 最终修正（若有）
  → Output Pose
```

当前 17 个 Montage 都使用 DefaultSlot，所以第一轮继续沿用它，先验证动作互斥。以后确实需要上半身独立动作，再增加独立 Group / Slot 与 Layered Blend；加多个 Slot 并不会自动提供动作优先级。

如果状态转换使用 Inertialization，其下游必须有对应节点；源动画停止求值后，后续 Notify 也不继续正常触发，所以关键清理不能只放在动画最后一帧。[Epic 混合节点文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine)

落地再跳：JumpEnd→JumpStart 的条件是新跳跃已提交 / 再次离地，JumpStart 重进时从头播放；不要等完整落地收尾才能接收跳跃。Loop 与落地判定读取物理状态。枚举混合的 Default Pose 始终连有效的 Idle / Locomotion，不留空造成参考姿态。

### 移动速度重新标定

以下为源根轨迹在 Rate Scale=1 时的水平平均速度，单位 cm/s，网格当前缩放为 1：

| 动画 | 原始时长 | 根位移 | 原始速度 | 建议游戏速度 | 建议样本倍率 |
|---|---:|---:|---:|---:|---:|
| Walk_F | 1.333 s | 198.24 cm | 148.68 | 150 | 1.01 |
| Run_F | 0.733 s | 396.47 cm | 540.64 | 450 | 0.83 |
| Sprint | 0.533 s | 396.47 cm | 743.38 | 650 | 0.87 |
| Crouch_Walk_F | 2.000 s | 168.50 cm | 84.25 | 100 | 1.19 |

计算：`基础速度 = 水平根位移 / 动画时长`；`播放倍率 = 目标移动速度 / 基础速度`。对于带回撤轨迹的攻击 / 闪避，“路径长度”和“净位移”不同，不能照此当作循环步速。

**顺序**：先把 Walk_F 的源 Rate Scale 从 0.5 统一回 1；再设置样本倍率。如果保留 0.5，就必须把它计入总倍率，不能把表里的倍率直接再乘上去。当前 Walk_F 在默认节点倍率下对应约 74.34 cm/s，明显不同于其他方向。

在 UE 操作：

1. 打开 `BS_SwordLocomotion`，将同一方向族的走 / 跑样本分别统一放在建议 150 / 450；Sprint 在 650。当前 Walk_R 行约 203.60，其余约 200，也要整理成同一行。
2. 各样本配置对应倍率。暂时保留 Axis to Scale Animation=None，避免又叠加一层自动倍速。若后续采用速度缩放，则重新定义唯一倍率来源。
3. `GroundSpeed → Speed`，`Direction → Direction`。地面速度使用 Velocity.Size2D，不用 MaxWalkSpeed 代替实时速度。
4. 当前站立 BS 的方向已经开启 Wrap Input，保留；蹲走还没开启，建议补上并保证 ±180° 的后退样本一致。不要对 -180 到 180 的角度直接做普通线性插值。
5. 先用方向平滑约 0.10～0.15 s、速度平滑约 0.10～0.20 s 做起点。站立 BS 目前已有 0.10 / 0.20 s，蹲走为 0；不要额外在多个层级叠长延迟。
6. 添加左右脚着地 Sync Marker，混合时对齐步态相位；脚滑再用录屏逐帧校准接触脚，不只调整 CharacterMovement 数值。

### Sequence / Montage / Notify 分工

- 循环姿态与移动混合用 Sequence / BlendSpace；需要业务开始、结束、打断和根运动控制的一次性动作优先用 Montage。
- Sequence 内原有 Trail 通知会随其在 Montage 中播放而触发，不必在两处重复添加。游戏伤害窗口放在项目 Montage 统一编辑，更容易区分同一动画的玩家与敌人用途。
- 原资源 Trail 引用 Cascade `P_Trail`，挂点为 `Weapon_R_Trail_A/B`；现有伤害扫掠使用武器网格 `BladeBase/BladeTip`。这两套名字与承载组件不同，必须分别核对，不要直接把其中一个名字替换到所有位置。
- `P_HitPoint` 作为“命中特效”应由真实命中结算触发，空挥不生成。原 Sequence 中按固定时间播放的 P_HitPoint 若也保留，会产生空挥特效或重复特效；在派生资源中按实际需求整理。
- 使用三种独立事件：Damage Window、Trail Window、ChainPoint / Cancel Window。当前 `AttackWindowNotifyState` 已区分 Damage、ComboInput、WeaponEffect，可以兼容迁移。

通知是动画时间轴事件；挂点留空的特效可能从物体根位置生成。按实际承载 SkeletalMesh 配置 Socket，而不是仅按角色胶囊位置生成。[Epic Animation Notifies 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-notifies-in-unreal-engine)

## 9. 分阶段实现，不一次推翻全部代码

### 第一阶段：清理与地面核心

1. 在 UE 修正第四段 Warp Target Name，确认额外缺骨架 AnimBlueprint 的引用。
2. 校准 Walk / Run / Crouch 的倍率和 BlendSpace，保留现有相机锁定。
3. 建立统一 Action 入口、移动 / Yaw 策略与统一结束清理；已有 Combat 命中代码不重复实现。
4. 保留四个基础 Montage，分离输入缓存与 ChainPoint，重新编辑取消窗口。
5. 验证四向根运动闪避、持续格挡与受击回到 GuardHold / Free。

### 第二阶段：完整空地循环

1. 升龙提交点一次性发射；按 HitReactionProfile 给敌人击飞。
2. 空中 01→02 连击，不走原来统一向下 Launch 分支。
3. 05 三段下砸与实际落地接触点对齐。
4. 敌人 Landed→Down→GetUp→AI，全部覆盖死亡打断。

### 第三阶段：丰富而不增加混乱

1. 把 02 / 03 动作集用于不同武器风格或精英敌人，复用同一个 Action 接口。

3. 评估有限的距离 / 方向修正、攻击命中停顿、镜头震动和音效；玩家与敌人共享规则而使用不同参数。

可新增资源的命名建议：`DA_SwordActionSet`、`DA_Action_Sword_Light_01…04`、`DA_Action_Sword_Rising`、`DA_Action_Sword_AirLight_01/02`、`DA_Action_Sword_Dive`、`AM_Sword_SprintAttack`、`AM_Turn_L90/R90/L180/R180`。这些是设计名称，目前尚未创建。

## 10. 验收清单

| 场景 | 应当看到的结果 |
|---|---|
| 普攻刚起手提前再点一次 | 只缓存下一刀，在 ChainPoint 消费，不要求玩家卡窗口点击 |
| 高频连点后松手 | 最多消费当前单槽缓存，不延迟自动打完长队列 |
| 普攻 / 受击 / 格挡时按住 WASD | 按动作策略锁输入；结束正确释放，无残留锁 |
| 空中按右键 | 保留惯性和重力；角色不突然刹停或悬空 |
| 闪避前后左右及斜向输入 | 选对动画；斜向按四向量化规则表现，非暗中永远播放前闪 |
| 攻击中目标移动到背后 | 出刀阶段不瞬间追转 180°；下一次起手再重新取方向 |
| 第四段攻击锁定目标 | WarpTarget 有效；接近时保留胶囊间距，无穿模 |
| 升龙 / 下砸被击中、被打断或跌出平台 | 伤害窗口和特效正确关闭；物理继续，下落状态正确 |
| 被击飞敌人在高处停留 | 不因计时结束在空中站立；实际落地后进入倒地与起身 |
| 起身中被击杀 | 不重新启动 AI，不补出残留攻击 |
| 长按防御连续挡两次 | 两次都扣耐力 / 减伤，BlockHit 后仍回 Hold；耗尽后破防 |
| 空挥与砍中敌人 | 空挥只有刀光；真实命中才有命中火花，单 HitGroup 不重复扣血 |
| 后退左右跨 ±180°、低速反向 | 无方向瞬跳，脚步相位衔接，不突然闪回正面 |
| 30 / 60 / 120 FPS 与多个敌人 | 输入消费次数、击中次数和恢复条件一致；高速刀刃无明显漏判 |
| 死亡后重新开始 | 相机、输入模式、动作缓存、计时器、HP/SP 与移动恢复初始化状态 |
